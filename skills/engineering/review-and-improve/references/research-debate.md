# Evidence-based research debate

Use only when the user explicitly requests a team debate or an independent research reviewer team. Compare ordinary alternatives directly. This reference supplies the research method. Use `multi-agent-coordination` when installed for backend, account/data boundaries, model selection, concurrency, worker lifecycle, and integration; otherwise follow the actual native tools and host permissions for those responsibilities. If no suitable delegation is available, disclose that limit and give a direct comparison without claiming independent agents ran.

## Frame competing positions

Identify the decision, constraints, credible alternatives, and evidence that could change the ranking. Use only enough distinct positions to cover the material alternatives. Give each a clear question and a common comparison basis. A perspective may advocate for a position, but must investigate its strongest weakness and the strongest alternative too.

## Independent research

Assign bounded questions to available reviewers before showing them others' conclusions. Request traceable primary evidence where research is needed, applicability to the actual conditions, practical trade-offs, implementation difficulty when relevant, and the largest uncertainty. Preserve enough detail and source locations to assess the argument; paper-count and character quotas are not evidence quality.

## Challenge and revision

Exchange the findings and request evidence-based rebuttal of the material weak points. Reuse existing reviewers when practical. A bounded rebuttal and response usually suffice; add a round only when a remaining disagreement can change the decision and a further check can resolve it. Stop when no new useful evidence or argument emerges. Agreement is not a requirement to finish.

## Rank and decide

The lead assesses the evidence, resolves contradictions, and owns the final recommendation. Rank viable directions with calibrated confidence, key evidence, acknowledged weakness, and a useful next step. Separate agreement from unresolved issues and identify a small discriminating experiment or source check when uncertainty changes the choice. Keep a credible fallback when useful.

If the user requests voting, collect each reviewer's actual ordered ballot before calculating an aggregation such as a Borda count. State the ballot set and scoring rule. Treat the aggregate as a description of reviewer preference; evidence and an explicit decision rule determine the recommendation. Do not invent a vote from the lead's ranking or present consensus as validation.

Deliver the question, positions considered, work actually performed, ranking and reasons, unresolved differences, and the next decision or experiment. Match the response language and depth to the user. Team research does not authorize operational changes or publication.
