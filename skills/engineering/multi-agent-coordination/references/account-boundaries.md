# Account and content boundaries

Before dispatch, classify the actual inputs and outputs using the user's environment policy. Private company context must remain on a verified authorized company route unless the user and applicable policy explicitly permit the exact transfer. A personal model subscription, available provider name, or company-sounding profile label does not establish that route.

Inspect non-secret host/provider/runtime evidence. Never inspect or copy credentials to prove access. Keep the chosen account throughout the task; unavailable models may use only an available, authorized same-account alternative. Missing required route evidence blocks affected dispatch while independent permitted work may continue.

Apply the same boundary to task titles, prompts, progress, reviewer feedback, artifacts, and saved state. A generic coordinator does not gain permission to receive restricted details. Use redacted structural summaries only when the actual policy permits them, and never relabel company content as public merely to make a tool work.

Resolve device-specific wrapper names, catalogs, endpoint configuration, and policies from current local instructions. Do not transport these settings with a personal skill bundle. This portable reference supplies checks; it neither grants account access nor replaces a stricter local policy.
