# Concise Work Writing

Choose the form for the actual reader and task. Keep a small message small, and give a document enough structure to be useful. Write English by default for workplace artifacts; follow a requested language, template, or tone.

## Choose the context

Infer the destination, audience, purpose, and relationship from the request and supplied conversation. A service name alone does not choose the format. A DM to a manager is not automatically a progress report. Ask only when a missing fact would materially change the draft.

| Context | Default presentation |
|---|---|
| Jira ticket body | Smallest useful sections and compact bullets. Explain the problem or outcome, scope, and supported completion conditions. Use `to-tickets` when installed for decomposition, dependencies, and ticket-content decisions. |
| Jira ticket comment | Lead with the answer, change, finding, or question. Short prose for a small update; short bullets for distinct progress items. Add the supplied evidence or next step when useful. |
| One-to-one DM | A short, direct, courteous message using only context this recipient is known to share. Greeting or thanks when it fits; no routine heading or sign-off. |
| Broad-channel question | Enough context for someone outside the immediate discussion, followed by a precise, answerable ask. Keep relevant constraints, attempts, and uncertainty. |
| Broad-channel sharing | Say what is being shared and why it is useful, then give the supplied link or takeaway. Include an invitation only when intended; a share does not need an invented request. |
| Casual internal-team exchange | Respond to the current turn with natural, concise sentences or an appropriate short acknowledgment. Contractions and mild informality fit when the relationship is established. |
| Technical document or wiki | Reader-level headings, grouped evidence or process bullets, and relevant code/visuals. Number sequences when order matters. Use complete sentences for reasoning or qualifications. |
| Report or manager update | Preserve the requested reporting format. Use `manager-report` when installed for progress-update content; read [report structure](references/reports.md) for report planning or style, then only the relevant standards. |

For comments, DMs, channel messages, or other text drafted as the user, read [conversational writing](references/conversational-writing.md). Use a private voice profile only when supplied or configured by the current environment. If it is missing, use the context guidance and draft normally; never claim a personal match you have not established.

## Write and check

1. Keep the point, answer, or ask easy to find. Reuse relevant supplied context; omit repeated background and implementation details the reader does not need.
2. Group related details into a few useful concepts. Structured documents may use compact phrases and verb-led bullets; conversational messages use natural grammar. Preserve the source's meaningful explanation rather than compressing everything into fragments.
3. Preserve facts, identifiers, numbers, dates, links, scope, uncertainty, attribution, questions, and commitments. Keep an investigation distinct from a fix, a proposal from a decision, and a suggested date from an agreed deadline. State technical details when they affect the reader's understanding or action.
4. Match tone to the specific audience without inventing familiarity, emotion, authority, or urgency. Existing samples and explicit corrections are evidence; generic adjectives alone do not establish a personal voice.
5. Use punctuation for clarity. `--` is allowed when natural; neither add nor remove dashes by formula. Keep code, commands, identifiers, and URLs intact.
6. Return the usable draft, with only material missing facts or necessary caveats outside it. Check meaning and context fit once before delivering; routine writing does not start an interview, profile update, research sweep, or a separate review team.

This skill controls presentation. Domain workflows retain content and evidence requirements; product-specific tools and write guards retain permission and delivery rules. Drafting alone grants no authority to send or publish.
